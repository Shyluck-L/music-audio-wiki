# 位元率（Bitrate）與檔案大小

> **一句話白話結論**：位元率代表播放音訊時每秒消耗的資料量，數值越大，代表每秒傳輸的資訊越多，檔案也越大。

## 概念說明
位元率（Bitrate，又稱碼率或資料傳輸率）是指數位音訊在單位時間（通常為每秒）內傳送或處理的資料量，單位通常為千位元/秒（kbps）或千位元組/秒（kB/s）。

在未經壓縮的原始音訊（如 PCM）中，位元率由「取樣率」、「位元深度」與「聲道數」三者相乘直接決定。未壓縮音訊的資料量極為龐大，若要在網路串流或行動裝置上順暢播放，就必須透過壓縮技術降低位元率。

## 重點整理
* **未壓縮音訊的資料量由三要素相乘決定**：
  * **計算概念**：每秒資料量（位元率）= 每秒取樣次數（取樣率）× 每次量測使用的位元數（位元深度）× 聲道數。
  * **日常規格實例**：以常見的雙聲道數位影音規格（48 kHz、16-bit）為例，每秒會產生約 1.5 Mbps 的資料量（換算約每秒 192 KB；若為標準 CD 規格的 44.1 kHz / 16-bit，每秒則約為 1.4 Mbps / 176.4 KB）。
* **為什麼未壓縮檔案不適合直接傳輸？**
  * 按照上述每秒約 192 KB 的資料消耗，一首短短 3 分鐘（180 秒）的未壓縮歌曲，檔案體積就高達 **34.5 MB**。
  * 若要在行動網路或串流平台上流暢播放多首歌曲，直接傳輸未壓縮資料會對頻寬與硬碟帶來極大負擔，這正是音訊必須進行壓縮的根本原因。
* **壓縮編碼的三種位元率控制方式**：
  * **固定位元率（CBR, Constant Bit Rate）**：整首曲子無論簡單安靜或熱鬧激昂，均以完全固定的資料量編碼。適合語音通話或網路頻寬極度受限的環境。
  * **可變位元率（VBR, Variable Bit Rate）**：以「維持恆定音質」為核心，在複雜段落自動投入更多位元、單純或安靜段落減少位元，能用最省的容量達到最好的聽感，是性價比最高的選擇。
  * **平均位元率（ABR, Average Bit Rate）**：設定一個目標平均值，在允許微幅彈性變動的同時，讓最終檔案大小便於精確預測。

## 生活類比
> [!NOTE] [補充說明] 生活類比
> 位元率就像「水管每秒流出的水量」：未壓縮音訊如同沒有龍頭調節的大水管，水流傾瀉而出（佔用大量頻寬與硬碟）；有損壓縮編碼技術則像智慧節水器，在需要大量水的地方供水，不需要時關小，讓水流（資料量）大幅減少，卻依然滿足你的洗滌需求（聽覺感受）。

## 實務應用與選擇建議
* **行動網路與網路廣播**：受限於頻寬，適合採用有損壓縮格式，搭配較低位元率（如 128 kbps～256 kbps）。
* **高品質音樂串流**：主流串流平台常提供 256 kbps 或 320 kbps（AAC/MP3 等級），在聽感上已極接近原始母帶，同時兼顧載入速度。
* **典藏與離線聆聽**：若儲存空間充裕，可選擇無損壓縮格式（FLAC/ALAC），位元率通常落在 700 kbps～1000 kbps 上下（約為未壓縮 PCM 的一半大小）。
